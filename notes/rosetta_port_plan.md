# 레포 1의 Rosetta 스테이지를 어떻게 옮기는가

H1의 `dG_separated` 쪽입니다. 레포 1(`vhh-mpnn-selfconsistency`)의
델타 A를 그대로 쓸 수 없는 이유와, 무엇을 바꿔야 하는지를 적습니다.

**착수 전 조건: 설계·대조 각 50건 완료 + 서열 설계(ProteinMPNN) 완료.**
사이드체인이 없으면 Rosetta 계면 점수는 계산되지 않습니다 — H2a에서
4.5 Å 기준이 0을 낸 것과 같은 이유입니다.

---

## 그대로 가져오는 것

| 요소 | 레포 1 | 여기서도 같음 |
|---|---|---|
| `InterfaceAnalyzerMover` | `A_B` 두 사슬 | ✅ 출력이 A(binder) + B(타깃) |
| `set_pack_separated(True)` | 필수 | ✅ **이 한 줄이 타당성을 좌우합니다** |
| `FastRelax` 반복 + 중앙값 | N_REPEAT회, 평균 아님 | ✅ |
| 지표 | `dG_separated`, `hbonds_int`, `unsat_hbonds` | ✅ |
| 단위 경고 | REU ≠ kcal/mol | ✅ |
| 라이선스 고지 | 비상업 판단은 저자의 것, 독자에게 이전 안 됨 | ✅ 복사 필요 |

생성자 버전 차이(`DockingPartners.docking_partners_from_string` →
문자열 → jump)의 3단 폴백도 그대로 씁니다. PyRosetta 2026.x에서
`InterfaceAnalyzerMover('A_B')`가 `TypeError`를 냅니다.

---

## 바꿔야 하는 것

**① 입력이 native 백본이 아닙니다.**

레포 1은 결정 구조(1.65 Å)에 설계 서열을 threading했고, 그래서
"백본은 실험 구조"라고 말할 수 있었습니다. 여기서는 백본 자체가
RFdiffusion 생성물입니다. 따라서

- `dG_separated`는 **생성된 백본이 옳다는 가정 위에서만** 의미를 갖습니다.
- 그 가정을 지지하는 독립 근거가 필요합니다 → AF2 재예측의 scRMSD/pAE.
  **H1의 AF2 단계가 Rosetta보다 먼저 와야 합니다.** 순서를 바꾸면
  "틀린 백본의 계면 에너지"를 보고하게 됩니다.

**② 양성 대조군이 native 복합체입니다.**

레포 1에서는 native 서열을 native 백본에 올린 것이 양성 대조군이었습니다.
여기서는 **4ZQK 전체(PD-L1 사슬 A + PD-1 사슬 B)** 가 양성 대조군입니다.
실제 결정된 복합체이므로, 여기서 좋은 `dG_separated`가 나오지 않으면
지표를 쓸 수 없습니다 — 사전 등록 §4의 판정이 그대로 적용됩니다.

> PD-1 사슬 B에는 **84 → 93 사이 8잔기 결손**(85–92)이 있습니다(무질서 루프).
> 결손을 메우지 않고 계산하면 양성 대조군이 실제보다 나쁘게 나올 수
> 있습니다. 메우는 방법(PDBFixer / RFdiffusion partial diffusion)과
> 메우지 않은 값을 **둘 다** 보고하고, 판정은 메운 쪽으로 합니다.

### 실측 (2026-11-03): 이완 없이는 양성 대조군이 실패합니다

위 ②의 우려는 가설이 아니라 **이미 측정되었습니다.** `scripts/ala_scan.py`를
4ZQK 전체 복합체(사슬 A 874원자 + B 776원자, 결손 미보정)에 돌린 결과:

```
[WT] dG_separated 중앙값   +94.05 REU
     hbonds_int 5.0, dSASA_int 1671 A^2
```

**부호가 양수입니다.** 실제 결합하는 공결정인데 "결합 상태가 분리 상태보다
94 REU 나쁘다"고 나왔습니다. `dSASA_int` 1671 Å^2 은 PD-1/PD-L1 계면으로
타당한 값이므로 계면 자체는 올바르게 잡혔습니다. 문제는 에너지입니다.

원인은 **결합 상태를 이완시키지 않았다는 것**입니다. 결정 구조는 Rosetta
점수 함수에서 보면 작은 충돌과 비최적 결합각을 갖습니다. `pack_separated`
로 분리 상태는 재배치해 그것을 풀 수 있지만 결합 상태는 그대로 묶여
있습니다. 그 비대칭이 양수로 나타납니다.

뒷받침하는 신호가 Ala 스캔 하위 순위에 있습니다.

| 잔기 | ddG (REU) | 읽는 법 |
|---|---|---|
| A113 ARG | −8.15 | 없애면 계면이 8 REU 좋아진다 |
| A124 LYS | −14.57 | 없애면 14.6 REU 좋아진다 |

공결정의 계면 Lys 가 결합을 14 REU **방해한다**는 것은 물리적으로
설득력이 없습니다. 이완되지 않은 구조의 짝 없는 전하·충돌이 Ala 치환으로
해소된 것으로 읽는 것이 자연스럽습니다.

**결과적으로 바뀌는 것**

- `dG_separated < 0` 같은 **절댓값 기준은 쓸 수 없습니다.** native
  복합체조차 통과하지 못합니다. 레포 1에서 AF2의 ipTM 이 native 에서
  0.12 가 나와 지표를 못 쓰게 된 것과 **같은 종류의 실패**이며, 같은
  방식으로(양성 대조군을 먼저 돌려서) 미리 잡혔습니다.
- 아래 실행 순서에 **이완 단계가 먼저 와야 합니다.** 레포 1의 델타 A는
  이미 그렇게 하고 있으므로, 이식할 때 순서를 빠뜨리지 않는 것이 핵심입니다.
- Ala 스캔의 **상위 순위는 유지됩니다.** 양수 오프셋은 WT·돌연변이 양쪽에
  공통이고 ddG 는 차액입니다. 다만 큰 음수 값은 오프셋의 영향을 직접
  받는 영역이므로 보고하지 않습니다.

---

**③ 음성 대조군이 다릅니다.**

레포 1은 shuffle·random 서열이었습니다. 여기서는 비-에피토프 배치가
이미 음성 대조군 역할을 합니다. 추가로 서열 수준 대조군(설계 서열의
shuffle)을 넣으면 "백본이 좋은가"와 "서열이 좋은가"를 분리할 수 있으나,
규모가 2배가 되므로 **다음 단계로 미룹니다.**

**④ 좌표계 주의가 그대로 적용됩니다.**

`FastRelax`는 구조를 변형합니다. H2a는 **이완 전** 좌표에서 계산했으므로,
Rosetta 결과와 같은 표에 놓을 때 각주를 달아야 합니다. H2a를 재계산하지
않습니다.

---

## 실행 순서

```
1. ProteinMPNN      binder 사슬 서열 설계 (타깃 고정)
2. AF2 initial guess 복합체 재예측 -> pAE_interaction, scRMSD
   └ 양성 대조군(native PD-1) 먼저. 통과 못하면 H1을 "측정 실패"로 보고
3. FastRelax        결합 상태를 이완. 생략하면 dG_separated 가 양수가 됩니다
   └ 위 "실측" 절 참조. 양성 대조군으로 음수가 되는지 먼저 확인
4. PyRosetta        2를 통과한 구조에만 dG_separated / hbonds_int / unsat_hbonds
   └ 양성 대조군(4ZQK 복합체) 먼저. 같은 판정 규칙
5. 그룹 비교        설계 50 vs 대조 50, 중앙값
```

**4는 2를 통과한 것에만 돌립니다.** 모든 설계에 돌리면 "AF2가 신뢰하지
않는 구조의 계면 에너지"가 섞이고, 레포 1에서 S2 AF2 복합체를 입력에서
제외한 것과 같은 이유입니다.

## 환경

PyRosetta·PyMOL은 **네이티브 Windows에서 동작하지 않습니다.**
레포 1에서 검증된 WSL2 환경을 그대로 씁니다.

| | |
|---|---|
| OS | Ubuntu 22.04 (WSL2) |
| Python | 3.10 (`/usr/bin/python3 -m venv`, conda base 비활성) |
| PyRosetta | 2026.39 `PyRosetta4.Release.python310.ubuntu` |

**함정:** conda `base`가 활성인 채 venv를 만들면 conda의 Python으로
만들어집니다. `conda deactivate` 후 `/usr/bin/python3`를 명시하십시오.

**비용 실측:** 이완 없는 계면 점수만이면 22잔기 x 4회 = 88회 계산이 2.2분(설계당 약 1.5초)이었습니다. 이완을 넣으면 레포 1 기준 설계당 약 32초로 **20배** 늘어납니다.
100건 × 3반복이면 약 2.7시간. **먼저 2건으로 재고 총량을 계산한 뒤**
본실행하십시오.
